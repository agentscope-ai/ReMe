# 附录 A：记忆系统优化案例

本附录从两次优化运行中提炼可迁移的设计措施。两次运行采用相同的文件化记忆框架：写入阶段把对话整理为带来源引用的笔记，查询阶段由回答 Agent 检索、读取笔记和原始对话，并在有限工具调用预算内作答。以下按问题及其解决机制组织，而非按候选版本或实现文件罗列。两次运行的验证集均偏向诊断与迭代；不同轮次独立抽样的聚合分数不宜直接比较。

## A.1 BEAM：长对话中的覆盖、顺序与证据可达性

1. **让检索窗口同时容纳整理后的记忆与原始证据。** 该系统既保存压缩后的笔记，也保留逐字转录；后者数量约占索引块的 95%。如果只按相关性分数截取前几个块，窗口很容易被转录占满，跨片段整合出的笔记反而不可见。优化时先按来源控制窗口构成：优先展示笔记，同时为转录保留固定槽位，使 Agent 既能利用整理好的结论，也能核对原话、数字与时间顺序。重排只改变候选的先后，不删除落在窗口外的块；尤其要在“已返回”去重标记之前重排，否则未展示的证据可能被误标为已见，后续也无法取回。这里的设计要点是：混合记忆库的检索质量取决于*窗口里的来源比例*，并非只取决于单块排序。

2. **压缩搜索响应时，保留通向原文的路。** 长转录片段使多轮搜索成本迅速上升，但直接截断又可能把答案藏在被省略的部分。该运行先给响应设字符预算，并为每个条目保留路径和行区间；展示不下的正文仍以可定点读取的引用出现。随后，因“从头截断”反复漏掉笔记中后部的事实，压缩粒度进一步降到行：按查询词的区分度、数字及标题线索选取证据行，先覆盖多个命中，再用剩余预算补相邻上下文。无字面重叠时仍保留标题和摘要，以免丢掉语义检索命中的条目。这说明响应压缩应同时满足两个条件：当前窗口尽量显示与问题有关的证据，未显示的内容仍能被明确定位和读取。

3. **给“找全所有提及”提供全局视图，而非反复扩大 top-k。** 枚举和覆盖型问题的答案可能散布在许多会话中；相似度检索即使每次都返回高相关结果，也不能保证没有漏项。优化器因此从全部笔记派生一份按时间组织的紧凑索引，附在正常检索结果之后，并限制每个问题只自动投递一次。索引条目携带笔记路径，供 Agent 回读核实；同一会话的重叠笔记则合并近重复项，但保留兄弟笔记的访问路径。路由仅在经过离线校验的覆盖型问题上触发，以控制索引成本。一次回归还表明，按主题写成的索引会误导“首次提及顺序”问题：它看似提供了答案，实际丢掉了顺序证据。因而，全局索引适合回答“有哪些”，不能未经验证就代替回答“先后如何”。

4. **对顺序问题给出阅读路线，而不是代答的摘要。** 顺序题的证据横跨多个日期，单张笔记无法覆盖。此前的摘要式索引使 Agent 直接依据概述作答，省下 token 却答错先后关系。改进后的路线图仅列出按时间排列的笔记路径，引导 Agent 逐篇核对；进一步标注每篇笔记中“对话流”小节的行区间，使它只读取记录提及顺序和说话人的相关部分。该小节平均约占笔记的 30%，比整篇读取更容易落在工具与上下文预算内。这里的启发是：索引可以只负责导航；当答案依赖细粒度顺序时，过早把证据压成主题摘要反而会损失决定性信息。

5. **在写入时保存检索无法重建的关系。** 逐题追踪发现，一些失败并非没有找到笔记，而是笔记从未记录“谁说的”“何时首次提及”以及“新陈述是否取代旧陈述”。写入规则因此要求明确标注发言人，把助手建议与用户决定区分开；增加按实际对话顺序排列的记录；逐字保留影响后续回答的长期指令；遇到更新时保留新旧说法及其取代关系，而非静默覆盖。查询端可以重排已有文本，却无法从被压缩掉的归属、顺序和更新关系中恢复事实。这些字段应由预期问题反推到记忆结构中。

## A.2 LME-S：事实召回、聚合检索与回答校准

1. **写入短而自足的用户事实，减少“主题作文”对检索的稀释。** 基线笔记常把通用建议写得很长，却遗漏精确日期、数字或用户实际作出的选择；长篇泛化文本又使嵌入表示偏离具体事实。优化器为写入设定优先级：完整保留用户状态、偏好、决定及感受；逐字保留该会话特有的名称、日期、价格等；把通用解释压缩为一行。每个会话尽量形成一张笔记，并以可独立理解的“关键用户事实”开头。这既减少跨文件近重复，也使重要事实在切块和检索时更容易被单独命中。长度预算应先由通用背景承担，而不是以删去用户事实为代价。

2. **为有限窗口同时控制语义重复和来源集中。** 同一会话的相似笔记可能占满一个仅有数个槽位的窗口，而同一份原始转录的多个块又可能在渲染时合并为一条，造成“占了多个槽位却只交付一条证据”。前一问题用偏重相关性的最大边际相关性重排缓解：在保留高检索分数的同时，对与已选块高度相似的候选施加小幅惩罚；后一问题按文件来源限制窗口槽位，原始转录比笔记更严格。两种调整都只把超限或近重复块推迟，不从候选流删除。可推广的原则是：窗口应按最终能交付的*不同证据*来使用，而非机械地按检索块计数。

3. **在 top-k 之外增加低成本的目录索引。** “一共参加过几次”要求找齐每次提及，单次相似度检索却只保证返回最像的若干块。每张笔记已有名称和一句描述，因此可以遍历全部笔记的这一小段目录信息，以查询词匹配生成候选清单，再附在普通检索结果后。为避免“用户”等模板词把清单填满，词项须通过文档频率门槛；排序也由有区分度的最佳匹配词决定，而非累加大量弱匹配词。清单保留路径与命中附近的描述片段，使 Agent 知道该去读哪张笔记。这个索引的价值在于*覆盖全部笔记*：它处理的是 top-k 的覆盖盲区，不是试图取代语义检索。

4. **把目录索引延伸到事实条目，同时保留两层互补视图。** 一行描述终究是有损摘要：某次毕业典礼、某个岛名或具体就寝时间可能只写在正文里。改进后的索引逐张读取笔记，把 Markdown 列表中的自足事实拆成条目；命中时直接内联原句，让 Agent 不必为每条事实再发一次读取请求。事实层和目录层分别计算词频与排序，避免新增一层悄悄改变另一层的匹配标准；已在普通检索窗口展示过的事实则从索引中抑制，减少重复。目录层仍不可省，因为问题可能按会话主题发问，与事实原句没有共同词。两层分别回答“哪张笔记可能相关”和“其中哪条事实直接相关”。

5. **让索引常开但按问题调整宽度，并明确其证据边界。** 优化中曾尝试仅对枚举问题或显式请求投递索引，以避免无关匹配干扰回答；逐题核对却发现，该门控没有解决被归因于它的错误，反而让 Agent 在缺少线索时反复改写搜索，增加总 token。终选设计保留常开索引，但对查点问题只给较短清单，对枚举问题放宽条数，并在索引头部明确说明：关键词命中只是一条查证线索，非空清单不能证明问题中的实体或事件存在。这个反转提示，索引是否有用不能仅由提问措辞预测；对廉价索引，更有效的控制有时是限制输出规模并教会 Agent 核对证据含义。

6. **把“已检索到”与“答对”分开诊断。** 若干题中 Agent 已读到正确笔记，却因要求不存在的完成确认而过度弃权，或在指出问题前提错误的同时仍给出所求数值。回答规则因此补上时间锚定、按较新记录判断当前状态、区分实体边界，以及假前提下直接拒绝所求值等约束；随后又回退未经逐题证实、会反复增加 ReAct 提示成本的规则。对记忆系统而言，答案错误可能发生在写入、召回、证据解释和回答决策四个不同位置；在已经看到正确证据的案例上继续堆检索结果，通常不会修复决策错误。

两次运行共同表明，记忆优化不是单一的向量排序问题：写入结构决定哪些关系能够被找回，检索窗口决定有限预算内能看到哪些来源，派生索引补足 top-k 的覆盖盲区，而回答策略决定证据最终如何被使用。对于各轮独立抽样的验证结果，应优先依据同题配对和逐题轨迹判断具体机制的贡献，避免把捆绑修改带来的收益误归给其中一项。
